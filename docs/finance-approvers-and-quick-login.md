# المعتمدون الماليون المتعددون + الدخول السريع

## 1) المعتمد المالي: أكثر من شخص، وأول من يعتمد يُقفل الطلب

### ما تغيّر
| الملف | التغيير |
|---|---|
| `base44/shared/approverNotify.ts` | صار يجمع **كل** المعتمدين الماليين في المنشأة (`is_approver_finance`) ويرسل لكل واحد منهم بريداً + إشعاراً داخلياً. كان يُرسل لأول واحد فقط. |
| `base44/functions/approvalAction/entry.ts` | **قفل أول من يعتمد**: قراءة حديثة للسجل من المصدر قبل أي كتابة. إذا كان الطلب قد صُرف أو رُفض من معتمد آخر → يُرفض الإجراء بـ HTTP 409 ورسالة «سبقك معتمد مالي آخر — اعتمده فلان». ويُسجَّل `finance_id` / `finance_name` للمنفّذ على الطلب. |
| `src/pages/ApprovalsPortal.jsx` | إظهار رسالة الخطأ القادمة من الخادم (سبقك معتمد آخر / الطلب ليس في مرحلة الصرف) بدل تجاهلها، وإعادة تحميل الطابور فوراً. |
| `src/pages/Approvals.jsx` + `src/pages/EndOfService.jsx` | نفس القفل في مسار لوحة الإدارة: قراءة حديثة قبل الصرف، ورسالة واضحة، وتحديث القائمة. |
| `base44/entities/{LeaveRequest,LoanRequest,BusinessTrip}.jsonc` | حقول `finance_id` و`finance_name` (Settlement كان فيهما مسبقاً). |

### السلوك النهائي
1. الموظف يقدّم الطلب ← المدير المباشر ← الموارد البشرية ← **مرحلة المالية**.
2. عند الوصول للمالية: **كل** المعتمدين الماليين في المنشأة (مدير مالي، محاسب، غيرهما) يستلمون بريداً + إشعاراً.
3. أول واحد يضغط «تأكيد الصرف» أو «رفض» → يُحفظ القرار نهائياً على الطلب مع اسم المنفّذ.
4. الثاني إذا حاول: تُعرض له رسالة أن الطلب أُنجز بواسطة فلان، ويُحدَّث الطابور — **لا يُقبل اعتماد ثانٍ ولا يُكتب فوق الأول**.

> ملاحظة: منح الصلاحية لا يزال من ملف الموظف: خانة «تفعيل صلاحية الصرف المالي» (`is_approver_finance`). علّمها لأكثر من موظف وستعمل القاعدة تلقائياً.

## 2) الدخول السريع (بصمة / وجه / رمز الجهاز)

### كيف يعمل
يعتمد على **WebAuthn** وهي الطريقة المعيارية التي تتيح للمتصفح/التطبيق طلب تأكيد الجهاز نفسه:

| المنصة | ما يظهر للمستخدم |
|---|---|
| آيفون / آيباد | Face ID أو Touch ID، وإن لم يتوفرا → رمز شاشة الجهاز |
| أندرويد | بصمة الأصبع / التعرف على الوجه، وإن لم يتوفر → نمط أو PIN الشاشة |

الخادم يطلب `userVerification: "required"` فلا يُقبل مجرد وجود الجهاز — لا بد من بصمة/وجه/رمز.

### التدفق
1. **التفعيل (مرة واحدة):** دخول عادي برقم الهوية + كلمة المرور + الكابتشا → تظهر بطاقة «تفعيل الدخول السريع» → يضغطها → يؤكد بصمته → يُحفظ المفتاح العمومي على سجل الموظف.
2. **الدخول لاحقاً:** يفتح التطبيق → زر «دخول سريع بالبصمة أو رمز الجهاز» → يؤكد → تُصدر له جلسة بوابة كاملة **بدون كلمة مرور**.
3. **«لاحقاً»:** يكمل الدخول العادي ولا يُفعّل شيئاً.

### الملفات
| الملف | الدور |
|---|---|
| `base44/shared/webauthn.ts` | فك CBOR، تحويل مفتاح COSE، توقيع/تحقق التحدي، التحقق من تأكيد الدخول |
| `base44/functions/portalPasskey/entry.ts` | `register_options` / `register_verify` / `login_options` / `login_verify` / `disable` |
| `src/lib/passkey.js` | استدعاءات المتصفح: `navigator.credentials.create/get` + تلميح محلي للجهاز |
| `src/components/portal/PortalAuthCard.jsx` | زر الدخول السريع + بطاقة التفعيل |
| `base44/entities/Employee.jsonc` | `passkey_enabled`, `passkey_credential_id`, `passkey_public_key`, `passkey_rp_id`, `passkey_created_at`, `passkey_last_used_at` |

### ما يتحقق منه الخادم (لا تساهل)
1. التحدي (challenge) الذي وقّعناه نحن هو نفسه — وموقّع بـ HMAC وصالح 5 دقائق فقط (منع إعادة الاستخدام).
2. `type = webauthn.get` و`origin` مطابق لموقع النظام.
3. `rpIdHash` = SHA-256 لنطاقنا (منع استخدام مفتاح صادر لموقع آخر).
4. راية **UV** (تحقق المستخدم) مرفوعة — أي بصمة/وجه/رمز فعلي.
5. التوقيع صحيح على المفتاح العمومي المحفوظ لهذا الجهاز.

### تعطيله
- من الخادم: إجراء `disable` بجلسة بوابة صالحة يمسح المفتاح ويعطّل الخيار.
- من الجهاز: حذف بيانات الموقع / حذف «مفتاح المرور» من إعدادات الجهاز.
- تعطيل الموظف في النظام يمنع الدخول السريع فوراً (نفحص الحالة قبل إصدار الجلسة).

### حدود يجب معرفتها
- **التحقق الحقيقي يحتاج جهازاً**: لا يمكن اختبار بصمة داخل بيئة تطوير. جرّبه على آيفون وأندرويد حقيقيين.
- يتطلب **HTTPS** (أو `localhost` للتطوير) — وهو متحقق في الإنتاج.
- إذا كان التطبيق غلافاً (WebView) لا يدعم WebAuthn، سيفشل الزر بلطف ويبقى الدخول بكلمة المرور متاحاً. في هذه الحالة يحتاج الغلاف تمكين WebAuthn من إعدادات التطبيق الأصلي.
